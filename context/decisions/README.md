# Architecture Decision Records

Create an ADR only for significant durable decisions such as:

- Replacing a core technology
- Changing authentication or permission authority
- Changing tenancy or data ownership
- Changing event delivery or caching strategy
- Splitting the modular monolith
- Changing deployment units
- Introducing paid infrastructure

Use filenames such as `001-decision-title.md`.

```md
# ADR NNN — Title

## Status
Proposed | Accepted | Superseded | Rejected

## Context

## Decision

## Consequences

## Alternatives Considered

## Verification
```

Do not create ADRs for routine implementation details.
